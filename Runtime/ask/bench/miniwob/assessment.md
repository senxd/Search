# Search Ask agent parity: maturity and limits

Search's Python SDK, CLI, and stdio MCP server share its native Drive operations across tab control, navigation, semantic snapshots, screenshots, trusted input, artifacts, and consent. The main known parity gaps are MCP cancellation forwarding, unpressed mouse movement in an ordinary inactive window, and differences between WKWebView and Chromium behavior.

## What works

- The [Python SDK](../../SDK.md), [`./ask mcp` server](../../MCP.md), and [agent skill](../../../../skill/search-agent/SKILL.md) expose the same tab, navigation, snapshot, screenshot, and interaction path. MCP implements initialization, ping, tool listing, and calls. Mapping tests cover drag paths, screenshots, PDFs, downloads, and chunked artifact reads in [`sdk/test_search_mcp.py`](../../../../sdk/test_search_mcp.py).
- Search uses WKWebView and native NSEvents for trusted click, drag, type, and key input. Semantic snapshots provide versioned refs and locators; screenshots report CSS viewport dimensions and scale. Mouse actions await native event processing. Native dragging first sends an unpressed move to the source, drains pending mouse events, then waits 32 ms in the page world before pressing; the regression verifies that a 20 ms page poll observed the source first. Occlusion tracking is disabled while WebKit views are housed offscreen so native page animations advance. Stable tab selection keeps the child viewport fixed. [`Tests/Agent/native_check.py`](../../../../Tests/Agent/native_check.py) checks trusted event order, snapshot freshness, keyboard input, and the MiniWoB fixture's fixed viewport. These checks establish specific mechanics, not broad site coverage.
- PDF and completed-download artifacts are scoped to the agent session and can be read in chunks. The SDK and MCP expose list/read operations; native integration checks exercise both.
- Consent remains in Search. An agent may open and drive its own tabs. A user tab requires the Ask-panel chip before attach. Guard approvals need an open Ask chat and explicit socket opt-in; without that UI, a gated socket action returns `NEEDS_UI`. See the [Drive protocol](../../PROTOCOL.md) and [`Tests/Agent/native_check.py`](../../../../Tests/Agent/native_check.py).
- The MiniWoB runner pins the BrowserGym task catalog and page revision, fixes the seed, viewport, episode timer, model, effort, round cap, and wall deadline, and records Ask request/round audit data. It rejects forbidden browser tools and classifies provider and harness failures separately from scored task outcomes. Harness profile tests verify the Codex model/effort and terminal stream handling in [`harness.profile.bun.js`](../../test/harness.profile.bun.js).

## Completed MiniWoB run

The [completed run summary](results/miniwob-20260930-215414-252f70-20260930T205414Z/summary.md) scored all 125 pinned tasks with `codex/gpt-6-luna` at `xhigh`: 118 successes, 5 failures, and 2 timeouts, for 94.40%. The [failure review](results/miniwob-20260930-215414-252f70-20260930T205414Z/failure-review.json) covers all seven non-success outcomes and all 99 failed tool calls. It found no native event-delivery defect; 78 initial snapshots were rejected because the tab had not yet been attached, and the remaining calls were classified as expected ownership, visibility, occlusion, locator, or terminal-cancellation outcomes. The run took 84m 25.5s, with a 28s median task time and 1,042 rounds. Recorded completed-response usage was 4,942,136 input tokens, of which 2,947,072 were cached; output was 89,340 tokens, including 52,354 reasoning tokens. The run reported no infrastructure error.

The native audit verified all 1,165 request records used the same `codex/gpt-6-luna` and `xhigh` profile and that 125 completion events were recorded. One pre-stream provider HTTP 503 was retried successfully before generation began; no task episodes were replayed. All five runner input hashes match the final run metadata. The production credential store had no Codex entry, so the runner used the existing `~/.codex/auth.json` OAuth fallback through a temporary mode-0600 file, which was deleted after the run. No production data was modified.

Validation included a successful Swift build, 41 harness unit tests, 207 browser-driver checks, and the SDK, MCP, Guard, and request-receipt checks in [`sdk/check_baseline.sh`](../../../../sdk/check_baseline.sh). The live Echo suites [`native_check.py`](../../../../Tests/Agent/native_check.py), [`input_check.py`](../../../../Tests/Agent/input_check.py), and [`check.py`](../../../../Tests/Agent/check.py) passed. A three-task Luna pilot passed before the full restart. The final benchmark process and fixture server were stopped, its staged credential was deleted, and installed Search remained running.

## Current limits

- The MCP server does not forward MCP cancellation notifications to an in-flight SDK call. Calls are synchronous from the server's dispatcher; closing the process releases its socket session. This is documented in [MCP setup and limits](../../MCP.md).
- Trusted unpressed mouse movement still depends on WebKit's active-window state. MiniWoB keeps fixture pages in a virtual-key offscreen room so tab selection does not change the benchmark viewport or lose this input path. That fixture-specific hosting rule does not solve unpressed movement for a selected page in an ordinary inactive Search window.
- MiniWoB runs the pinned pages in WKWebView, while BrowserGym recommends Chromium because engine and layout behavior can differ. Treat the result as a Search baseline, not a direct comparison with published Chromium scores. The fixed seed also does not remove the catalog's four tasks marked nondeterministic in BrowserGym.
- A scored outcome means each of the 125 pinned task IDs has a recorded result, including a zero for an agent-finished non-terminal task. Do not interpret the score as 125 terminal successes: the run contains failures and timeouts as listed in the summary.

## Next step

Use the completed run to target general improvements: reduce the 78 pre-attach snapshot failures with attach-first guidance, improve coordinate and selection feedback, and have the agent verify task completion before stopping. Evaluate changes against the same pinned workload and retain its catalog, viewport, seed, model, and limits. Track WebKit-vs-Chromium differences and inactive-window input support as separate follow-up work.
